# 演示剧本（5 分钟）

> 目标：在 5 分钟内完整展示「感知 → 分析 → 决策 → 验证」闭环，突出**双阶段聚类**与
> **改进遗传算法调度**两个技术点，以及三类调度策略的仿真对比结论。
> 启动方式：项目根目录执行 `./start.sh`，浏览器打开 http://localhost:8000 。

**技术点**：聚类用 **DBSCAN 先做粗粒度区域识别，再用 K-means 在簇内二次聚类**；

## 附：常见问题 Q&A

**Q：为什么用模拟数据而不是真实 GPS？**
A：校园共享单车的真实轨迹涉及用户隐私且难以获取。系统用「随机游走 + 教学日潮汐模型」
生成高保真模拟数据源，数据管道（生成 → 清洗 → 缓存 → 推送）与真实系统完全一致，
替换数据源即可对接真实智能锁数据。

**Q：改进遗传算法相对普通 GA 的改进点？**
A：① 贪心最近邻构造初始种群（而非纯随机），初始解质量更高；
② 2-opt 局部搜索（子代以一定概率扰动 + 收敛后对最优个体精修）；
③ 精英保留策略（每代前 15% 直接进入下一代）。
染色体编码为节点排列，解码时按载重可行性切分车辆路径，保证任意排列都对应可行解。

**Q：地图是怎么标定的？**
A：在 `backend/config.py` 的 `MAP` 字段配置校园俯瞰图四角像素对应的真实经纬度，
`geo.py` 用双线性插值做像素 ↔ 经纬度双向映射。当前默认值为演示标定，
换成自己学校的俯瞰图时只需改这四组坐标。

**Q：为什么有时候看不到聚类圈？**
A：聚类扫描有周期（默认 60 秒），且需要单车密度达到 DBSCAN 的 `min_samples`。
若 `eps_m` 相对密度过大，整片校园会被串成一个大簇，接口会在 `stats.warnings`
中提示调参，可用 `POST /api/clusters/scan` 覆盖 `eps_m` / `min_samples` 试算。
